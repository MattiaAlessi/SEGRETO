🔑 Come funziona lo scambio ECDH
L'analogia dei colori
Alice sceglie rosso (segreto), Bob blu (segreto). Colore pubblico: giallo
Alice invia rosso+giallo, Bob invia blu+giallo → chiunque li veda non ricostruisce i segreti (tornare indietro dal miscuglio è praticamente impossibile)
Alice aggiunge il suo rosso alla miscela di Bob; Bob aggiunge il suo blu a quella di Alice
→ stesso colore finale, senza mai trasmettere i segreti. ECDH fa questo con la matematica delle curve ellittiche
I passaggi nel tuo codice

// 1. Ognuno genera la propria coppia (privata resta nel dispositivo)
const pair = await crypto.subtle.generateKey(
  { name: "ECDH", namedCurve: "P-256" }, false, ["deriveKey"]);

// 2. Viaggia SOLO questa, via DataChannel
const pubJwk = await crypto.subtle.exportKey("jwk", pair.publicKey);

// 3. Dopo aver importato la pubblica dell'altro:
const sharedKey = await crypto.subtle.deriveKey(
  { name: "ECDH", public: otherPublicKey },  // la sua pubblica
  pair.privateKey,                           // la tua privata
  { name: "AES-GCM", length: 256 }, false, ["encrypt", "decrypt"]);
// 4. → stessa chiave AES in entrambi i dispositivi ✨
Ogni messaggio poi: encrypt con AES-GCM + IV casuale nuovo → { iv, ciphertext }.

Perché serve il fingerprint?
Un attaccante potrebbe mettersi in mezzo e sostituire le chiavi pubbliche: Alice e Bob creerebbero ciascuno un segreto... con lui, non tra loro — senza accorgersene. Il fingerprint (hash breve delle chiavi pubbliche, es. 🎮🐼🔥) si confronta a voce: se coincide sui due dispositivi, le chiavi sono autentiche.

In una frase per il README: ECDH crea il segreto condiviso; il fingerprint verifica CON CHI lo stai condividendo.
